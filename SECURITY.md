# Security Policy

## Supported Versions

Read_Master is currently under active development. Security updates are applied to the latest version on the `main` branch.

| Version | Supported |
| ------- | --------- |
| Latest `main` branch | Yes |
| Older versions | No |

## Reporting a Vulnerability

Please do not report security vulnerabilities through a public GitHub issue.

Instead, report the vulnerability privately through the **Security** tab of this repository using GitHub Private Vulnerability Reporting.

Include the following information when possible:

- A description of the vulnerability
- Steps to reproduce the problem
- The affected page or feature
- The possible security impact
- Screenshots or proof-of-concept code
- A suggested solution, if available

Please do not access, modify, download, or disclose another user's private information while testing.

## What to Report

Security reports may include:

- Authentication or authorization bypasses
- Unauthorized access to books or downloads
- Exposure of user information
- Cross-site scripting (XSS)
- Firebase security-rule problems
- Malicious file-upload vulnerabilities
- Exposed passwords, tokens, or private credentials

## Response Process

The maintainer will review the report and aim to provide an initial response within seven days. Valid vulnerabilities will be investigated and fixed before details are publicly disclosed.

## Responsible Disclosure

Please allow reasonable time for the vulnerability to be investigated and corrected before sharing it publicly.
